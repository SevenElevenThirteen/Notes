# 微程序控制器与微程序设计

> 根据《计组_中央处理器-1.pdf》《计组_中央处理器-2.pdf》整理。微指令字段和控制器结构以课件中的模型为例，实际机器可采用不同编码、存储组织和微地址逻辑。

## 1. 从机器指令到微操作

| 名称 | 含义 |
|---|---|
| 机器指令 | 指令系统中的指令，规定对数据执行的宏观操作 |
| 微命令 | 控制部件经控制线发给执行部件的控制信号 |
| 微操作 | 执行部件收到微命令后完成的基本操作，如寄存器传送、ALU 运算 |
| 微指令 | 一个 CPU 周期内，对若干微命令及后续微地址的编码 |
| 微程序 | 实现一条机器指令的一段微指令序列；全部微程序共同实现指令系统 |

**基本思路**：把机器指令的执行过程分解成微操作，用微指令规定每一步；全部微程序存放于控制存储器中，运行时依序取出并发出控制信号。

```mermaid
flowchart LR
  I[机器指令 / IR.OP] --> M[微地址映射或入口选择]
  M --> CS[控制存储器]
  CS --> MIR[微指令寄存器]
  MIR --> C[控制字段：发出微命令]
  C --> E[执行部件：完成微操作]
  E --> F[状态 / 条件反馈]
  MIR --> N[顺序控制字段]
  F --> N
  N --> U[微地址寄存器 μPC]
  U --> CS
```

## 2. 微程序控制器的组成与运行

- **控制存储器（Control Store）**：保存机器指令系统对应的微程序，常以只读存储器实现。
- **微指令寄存器（MIR）**：保存当前读出的微指令，可概念性拆为：
  - **微命令寄存器**：保存/输出操作控制字段。
  - **微地址寄存器（μPC）**：保存下一条微指令地址。
- **地址转移逻辑**：按顺序字段、状态条件和指令操作码决定后继微地址。
- **微地址映射部件**：常用 ROM 查表，以机器指令操作码为索引，输出相应微程序入口。

运行步骤：

1. 取微指令并装入 MIR。
2. 控制字段发出微命令，执行部件完成微操作。
3. 顺序控制逻辑形成下一微地址；遇到条件分支时结合状态反馈选择分支。
4. 若该机器指令的微程序结束，则回到公共取指微程序。

微程序控制器结构规整、灵活、较易维护；代价是每个微指令周期需从控制存储器取微指令，速度通常受控制存储器访问影响。

## 3. 微指令格式

典型微指令包含两大部分：

| 字段 | 用途 |
|---|---|
| 操作控制字段 | 指定本周期执行哪些微操作/发出哪些控制信号 |
| 顺序控制字段 | 指定后继微地址，或选择测试条件以形成分支 |

课件的简化格式示例为 23 位：操作控制字段占前 17 位，顺序控制字段包含测试位与下地址信息。长度和字段边界仅是该模型示例。

### 微操作的相容与相斥

- **相容性微操作**：可以同时或在同一 CPU 周期内并行执行。例如不同资源上的独立传送。
- **相斥性微操作**：不能同时执行，常因争用同一硬件资源或互相矛盾。例如同一 ALU 同周期不能既执行加法又执行减法。

微指令并行度必须由数据通路能力决定，不能只因字段允许同时置位就假设操作可并行。

## 4. 微命令编码方法

### 直接表示法

操作控制字段的每一位直接表示一个微命令。

- 优点：直观、简单，控制输出直接。
- 缺点：字段较长，控制存储器容量较大。

### 字段编码法

将一组**相斥**微命令归为一个字段，再用译码器选择其中一项。

- 优点：减少微指令字长，节省控制存储器。
- 缺点：增加译码逻辑，可能增加延迟。
- 一个有 `n` 位的字段可编码 `2^n` 种状态；若全零编码用于“不发出命令”，可表示的具体命令数为 `2^n - 1`。
- 对含 `k` 个互斥命令的字段，通常需 `ceil(log₂(k+1))` 位（预留一个无操作码的情况下）。

### 混合表示法

对适合并行直出的控制信号使用直接表示，对相斥命令组采用字段编码，以折中字段长度、灵活性和速度。

## 5. 后继微地址的形成

### 计数器方式

顺序执行时令 `μPC ← μPC + 1`；非顺序执行时通过转移逻辑装入目标地址。

- 顺序微指令须在控制存储器连续单元中安排。
- 顺序控制字段短、结构简单；分支灵活性较弱。

### 多路转移方式

微指令给出候选后继地址，顺序控制字段指定测试方式，地址转移逻辑再根据状态标志、IR 位等选择一个分支。若使用 `n` 位条件，可形成最多 `2^n` 路选择（实际由字段设计决定）。

### 操作码映射方式

用 IR 的操作码查微地址映射表，得到该机器指令微程序的入口地址。常见实现是 ROM：

`IR.OP → 映射 ROM → 微程序入口地址`

### 选择逻辑的设计步骤

1. 列出全部微程序分支情形及相应条件（如指令操作码、进位标志、控制台状态）。
2. 为每种测试分配判别字段（如 `P1/P2/P3`），确定需要修改 μPC 的哪些位。
3. 写出各 μPC 位的逻辑表达式，并考虑时序脉冲（课件示例在 `T4` 更新）。
4. 根据有效电平选择与门、与非门等实现逻辑。

例如，若 `P1` 按 `IR3..IR0` 做 16 路分支，`P2` 按进位标志 `C` 做 2 路分支，`P3` 按 `IR5..IR4` 做 4 路分支，可分配不同判别条件来装载 μPC 的低位或高位；具体布尔式取决于微地址位分配与触发器有效电平。

## 6. 水平型与垂直型微指令

| 比较 | 水平型 | 垂直型 |
|---|---|---|
| 表示方式 | 多个微命令可在一条微指令中并行指定 | 设微操作码，由操作码指定较少的操作 |
| 并行能力 | 强 | 较弱 |
| 微指令字长 | 较长 | 较短 |
| 微程序长度 | 通常较短 | 通常较长 |
| 执行效率 | 并行能力强，执行一条机器指令往往较快 | 一条机器指令通常需更多微指令步骤 |
| 易读性 | 控制能力强，但设计/理解较复杂 | 形式接近机器指令，较容易理解 |

水平型的控制字段还可采用全水平（不译码）、字段译码或直接与译码混合编码。

## 7. 微程序控制中的时序

串行微程序控制器中，一个微指令周期通常包括**读取微指令 + 执行微指令**。为了和 CPU 控制同步，可令微指令周期与 CPU 周期相等。

课件示例：CPU 周期为 `0.8 μs`，含 `T1–T4` 四个等间隔节拍，每个 `200 ns`；可以用 `T4` 读取下一条微指令、`T1+T2+T3` 执行当前微指令。这是示例时序方案，不是固定要求。

## 8. 例题：微地址位数

机器有 32 条指令；公共取指微程序 2 条微指令；每条指令微程序平均 4 条微指令。若采用下地址字段直接指定下一条微指令：

`微指令总数 = 32 × 4 + 2 = 130`

需要能表示至少 130 个地址：`ceil(log₂ 130) = 8`，故下地址字段至少 **8 位**。

> 计数题的关键是把公共微程序也计入，然后用 `ceil(log₂ N)` 求地址位数。

## 9. 例题：字段编码长度

33 个微命令分成 5 个互斥类，分别含 7、3、12、5、6 个命令。若每个字段需额外编码一个“无操作”状态，则字段长度分别为：

`ceil(log₂(7+1)) + ceil(log₂(3+1)) + ceil(log₂(12+1)) + ceil(log₂(5+1)) + ceil(log₂(6+1))`

`= 3 + 2 + 4 + 3 + 3 = 15 位`

## 10. 易错点

- **微命令 ≠ 微操作**：前者是控制信号，后者是执行部件完成的动作。
- **机器指令 ≠ 微指令**：一条机器指令通常由多条微指令实现；微指令关联控制存储器，机器指令关联主存中的程序。
- **字段编码只适合相斥命令**；可并行的操作不应错误塞进同一个互斥字段。
- **水平型不是“一条微指令只做一个操作”**；其设计目标之一正是并行发出多个相容微命令。
- 计算下地址位数时，先求微程序总条数，再求能够覆盖该条数的二进制位数。
